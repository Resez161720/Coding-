# ระบบช่วยพิมพ์ Tag (Tag Print Assistant): เอกสารออกแบบ

วันที่: 2026-10-28
สถานะ: ผู้ใช้อนุมัติให้เริ่มสร้าง (แนวทาง A)

## 1. ปัญหาและเป้าหมาย

- โปรแกรมหลักบน AS/400 (จอเขียว 5250) ต้องใช้ต่อ แก้ไขตัวโปรแกรมหรือฐานข้อมูลไม่ได้
- มีคอมเครื่องเดียวที่ใช้กรอกผลผลิตและพิมพ์ tag พนักงานรันเครื่องต้องมาต่อคิว กรอกหลายหน้าจอ แล้วพิมพ์ tag ไปเสียบตะกร้า
- ปริมาณ 300–600 tag ต่อวัน, 30 เครื่องจักร, ชิ้นงานเกือบ 200 แบบ
- เป้าหมาย: พนักงานรันเครื่องไม่ต้องมาที่คอมอีก มี "คนพิมพ์ tag" 1 คนต่อกะ ใช้เครื่องมือนี้ช่วยให้ **เร็ว ง่าย และไม่ผิดพลาด**

## 2. ข้อจำกัดที่ยืนยันแล้ว

| เรื่อง | ข้อเท็จจริง |
|---|---|
| โปรแกรมจอเขียว | IBM Personal Communications (iSeries Access for Windows V6) มี Host Access Class Library (autECL) ให้โปรแกรมอื่นอ่านจอและกรอกช่องได้ |
| อุปกรณ์ในไลน์ | ห้ามมือถือ/แท็บเล็ต แต่ **ใช้เครื่องยิง barcode แบบพกพาได้** |
| สิทธิ์ติดตั้ง | มีสิทธิ์ admin บนคอมเครื่องหลัก |
| สีกระดาษ | พนักงานเปลี่ยนกระดาษเอง สีขึ้นกับประเภทงาน ส่วนใหญ่ผูกกับเครื่องจักร บางเครื่องทำได้หลายประเภท |
| การตรวจข้อมูล | ระบบเดิม **ไม่แจ้ง error** เมื่อกรอกผิด (ยกเว้นพิมพ์ตัวอักษรในช่องตัวเลข จะขึ้นแถบแดง) |
| การพิมพ์ | tag พิมพ์ทันทีเมื่อกด Enter ที่หน้ายืนยันสุดท้าย |

## 3. การทำงานแต่ละวัน (แนวทาง A ที่อนุมัติ)

**เตรียมครั้งเดียว:** ป้าย barcode เครื่องจักรและรถเข็น, การ์ดพนักงาน (เสียบไว้ที่เครื่อง), การ์ดคำสั่ง (เต็มตะกร้า / ตัวเลข 0–9 / จบ / NG / ยกเลิก), ตารางเครื่องจักร (สี, M/C Speed, Action), เวลาแต่ละกะ

**พนักงานรันเครื่อง:** ต้นกะเสียบการ์ดตัวเองที่เครื่อง ตะกร้าเต็มวางบนรถเข็นตามปกติ ตะกร้าไม่เต็มหรือมี NG ให้เขียนจำนวนไว้

**คนพิมพ์ เดินรอบ (~30 นาที):** ที่แต่ละเครื่องยิงตามลำดับ
1. ป้ายเครื่อง (ล้างข้อมูลของเครื่องก่อนหน้าทั้งหมด)
2. ใบสั่งงาน
3. ป้ายวัตถุดิบ D/O และ Coil
4. การ์ดดาย
5. การ์ดพนักงาน
6. ป้ายรถเข็น แล้ว "เต็มตะกร้า" หรือ ตัวเลข + "จบ" (ถ้ามี NG: "NG" + ตัวเลข + "จบ")

ตะกร้าถัดไปของงานเดิมยิงแค่ข้อ 6

**คนพิมพ์ ที่คอม:** นำเข้าข้อมูลจากเครื่องยิง → ตรวจ/แก้รายการที่ถูกเตือน → เลือกสี → ใส่กระดาษ → โปรแกรมกรอกจอเขียวและพิมพ์ทีละใบ → เดินส่ง tag ตามลำดับเส้นทาง

## 4. โครงสร้างโปรแกรม

โปรแกรม Python ทำงานบนคอมเครื่องหลัก หน้าจอเป็นหน้าเว็บในเครื่อง (`http://127.0.0.1:8765`) ไม่ต้องติดตั้งเว็บเซิร์ฟเวอร์เพิ่ม

| ส่วน | หน้าที่ |
|---|---|
| `thai_keyboard` | แก้ข้อความที่เครื่องยิงพิมพ์ออกมาเป็นภาษาไทยเพราะแป้นพิมพ์เป็นไทยอยู่ |
| `scan_parser` | แปลงข้อมูลจากเครื่องยิงเป็นรายการ tag |
| `masterdata`, `config`, `shifts` | ตารางเครื่องจักร/พนักงาน/รถเข็น, การตั้งค่า, คำนวณกะจากเวลา |
| `validation` | ตรวจข้อมูลก่อนกรอก และหาสีกระดาษ |
| `store` | ฐานข้อมูล SQLite: รายการ, สถานะ, ประวัติ, สีที่จำไว้ต่อใบสั่งงาน |
| `screen` | อ่านหน้าจอ 5250 หาช่องกรอกจากชื่อช่อง (ไม่ผูกกับตำแหน่งตายตัว) |
| `driver/pcomm` | เชื่อมกับ PCOMM ผ่าน autECLPS / autECLOIA |
| `driver/fake` | จอเขียวจำลอง 5 หน้า สำหรับโหมดทดลองและชุดทดสอบ |
| `flow` | ขั้นตอนกรอก 5 หน้าจอสำหรับ tag 1 ใบ |
| `runner` | รันทีละสี ถามใส่กระดาษ หยุดเมื่อเจอปัญหา |
| `app`, `web` + `static` | หน้าเว็บภาษาไทย (POST ต้องมีหัวข้อ `X-Tagbot` กันเว็บอื่นสั่งงาน) และ worker thread เดียวที่ถือการเชื่อมต่อจอเขียว |
| `code128`, `cards` | สร้างหน้าการ์ด barcode สำหรับพิมพ์ |

## 5. ขั้นตอนบนจอเขียวต่อ tag 1 ใบ

| หน้า | สิ่งที่โปรแกรมทำ | ตรวจอะไร |
|---|---|---|
| DEP012G1 | กรอก MFG ORDER NO. → Enter | ต้องไปหน้า G3 ถ้าไม่ไป = ไม่พบใบสั่งงาน |
| DEP012G3 | อ่าน ITEM NO., LOT SIZE; กรอก LOT M/O QTY → Enter | จำนวนดีต้องไม่เกิน LOT SIZE และไม่เกินยอดคงเหลือ |
| DEP012G4 | ตรวจแถว lot ใหม่ → **F5** (จุดที่ lot ถูกสร้างจริง) | ต้องมีแถวใหม่ที่จำนวนตรง |
| DTNOG1L2 | อ่าน M/O No.; กรอก Shift, Emp No., M/C No., Cart No., Good/Ng Qty, Die No., Remark 1, Remark 3, M/C Speed, Action → Enter | In Qty ตรง, ช่องไม่ล็อก (แถบแดง), สีตรงกับประเภทงาน (ถ้าตั้งค่า) |
| DTNOG1L4 (CONFIRM) | อ่านค่าทุกช่องกลับมาเทียบ → (ช่วงทดลอง: รอคนกดยืนยัน) → Enter = พิมพ์ | ทุกค่าต้องตรงกับที่ตั้งใจ ถ้าไม่ตรงหยุด |

ช่องที่ระบบใส่เอง (วันที่, เวลาเริ่ม/จบ, เลขกล่อง) โปรแกรมไม่แตะ ช่อง Tag No. และ Press Mat เว้นว่าง

## 6. รูปแบบ barcode

- การ์ดที่โปรแกรมพิมพ์: `MC-<เครื่อง>`, `CT-<รถเข็น>`, `EMP-<รหัส>`, `CMD-FULL`, `CMD-END`, `CMD-NG`, `CMD-UNDO`, `NUM-0` ถึง `NUM-9`
- เอกสารเดิม (ตั้งค่า regular expression ได้ใน `config.toml`): ใบสั่งงาน (เดือน 3 ตัว + ปี 2 หลัก + รหัส), D/O ขึ้นต้น `OP`, Coil ขึ้นต้น `OF`, ดายรูปแบบ `DIE.<เลข>`
- barcode ที่ไม่รู้จักจะถูกแจ้งตอนนำเข้า ไม่ถูกทิ้งเงียบ ๆ

## 7. การตรวจข้อมูลก่อนกรอก

ครบทุกช่อง, เครื่องอยู่ในตาราง (และ M/C Speed เป็นตัวเลข), พนักงานอยู่ในตาราง (ถ้ามีตาราง), รถเข็นอยู่ในตาราง (ถ้ามีตาราง), รูปแบบใบสั่งงาน/D/O/Coil/ดายถูกต้อง (D/O กับ Coil สลับกันไม่ได้), จำนวน > 0, รู้สีกระดาษ รายการที่ไม่ผ่านจะไม่ถูกส่งไปจอเขียว

**สีกระดาษ:** ใช้สีที่จำไว้ของใบสั่งงานก่อน (มาจากคนเลือกให้เครื่องที่ทำหลายประเภทงาน หรือเรียนรู้จาก `process_colors` ที่หน้า DTNOG1L2) ถ้ายังไม่รู้ใช้สีประจำเครื่อง

## 8. สถานะและการกู้คืน

| สถานะ | ความหมาย | ทำอะไรต่อ |
|---|---|---|
| รอพิมพ์ | ยังไม่เริ่ม | รันได้ |
| ล้มเหลว | หยุดก่อนกด F5 ไม่มีอะไรถูกบันทึกใน AS/400 | แก้แล้วลองใหม่ได้ |
| ต้องตรวจ | หยุดหลังกด F5 (lot ถูกสร้างแล้ว) | คนพิมพ์ทำต่อเองบนจอเขียว แล้วกด "ทำเองแล้ว" หรือ "ยกเลิก" |
| พิมพ์แล้ว | กด Enter หน้ายืนยันแล้ว | ส่ง tag |

กติกา: ผิดพลาดก่อน F5 → กด F1 (CMD1-RETURN) กลับหน้าแรก ข้ามรายการนั้นแล้วทำต่อ, ผิดพลาดหลัง F5 → **หยุดทั้งชุด** และไม่ทิ้งงานค้างกลางทาง บันทึกสถานะลงฐานข้อมูลก่อนกด F5 และก่อน Enter สุดท้ายทุกครั้ง

## 9. การทดสอบและการทดลองใช้

- ชุดทดสอบอัตโนมัติ (pytest) ใช้จอเขียวจำลองครบ 5 หน้า
- โหมด `demo` ใช้ฝึกคนพิมพ์โดยไม่แตะ AS/400
- ช่วงทดลองจริง: เปิด `confirm_before_final_enter` ให้คนกดยืนยันทุกใบ เริ่มจาก 3–5 เครื่อง 1 สัปดาห์ แล้วค่อยขยาย
- มีปุ่ม "บันทึกหน้าจอ" เก็บข้อความและตำแหน่งช่องเป็นไฟล์ ไว้ส่งให้ผู้พัฒนาปรับแต่ง

## 10. เรื่องที่ต้องยืนยันก่อนใช้งานจริง

1. กรณีมี NG: LOT M/O QTY = OK + NG ใช่หรือไม่ (ค่าเริ่มต้นในโปรแกรม: ใช่)
2. เวลาเริ่มของแต่ละกะ (ค่าเริ่มต้น A 08:00, B 16:00, C 00:00)
3. ข้อมูลใน barcode ของการ์ดดายที่มีอยู่ ตรงกับค่าที่กรอก (เช่น `DIE.4`) หรือไม่
4. หลังกด Enter หน้ายืนยัน จอกลับไปหน้า DEP012G1 หรือหน้าอื่น (ค่าเริ่มต้น `home_keys = []` คือถามคนพิมพ์ให้พาจอกลับเอง ไม่กดปุ่มบนหน้าที่ไม่รู้จัก)
5. ตำแหน่งช่องจริงบนจอ (ตรวจด้วยปุ่ม "บันทึกหน้าจอ" ในวันแรก)
